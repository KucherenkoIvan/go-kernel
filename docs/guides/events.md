# Domain Events: Delivery

How events generated by aggregates reach policies and projectors. The kernel side lives in [`events`](../../events/).

## The pipeline

```
aggregate methods          use-case (command)                     delivery
  PushEvent(...)   →   Save + Publish(ctx, tx, PopEvents())  →   policies / projectors
```

The use-case publishes through its feature's **event producer port** (see the [application layer](../architecture/3-application-layer.md)); the adapter behind that port decides the delivery mechanism:

| Implementation | Scope | Guarantee | Docs |
|---|---|---|---|
| `events.ChannelPublisher` | same service | at-most-once, in-memory | this guide |
| Transactional outbox → Kafka | cross-service, durable | at-least-once | [outbox](./outbox.md), [kafka](./kafka.md) |

Both sit behind the same port shape, so moving a feature from one to the other is a composition-root change — use-cases never know the difference.

## Commit-gating (why the naive version is wrong)

`Publish(ctx, tx, events...)` is called *inside* the transaction. Dispatching immediately would mean:

- handlers run before the commit and read **uncommitted** state;
- if the transaction rolls back, the events still happened — **ghost events** for state that never existed.

The channel publisher therefore buffers events on the transaction token via `ddd.AfterCommit` and enqueues them only after a successful commit. Rolled-back transactions publish nothing. With `ddd.NoTransaction` delivery is immediate.

`ddd.AfterCommit(ctx, tx, fn)` is public — it works with the postgres token and the `dddtest.FakeTxManager` alike, so this behavior is unit-testable.

## Wiring

```go
// cmd/<app>/main.go
pub := events.NewChannelPublisher(events.WithLogger(logger))

couponFeature := coupon.New(db, pub) // feature subscribes its handlers inside New

err := app.Run(ctx,
	app.Adapter{Name: "postgres", Close: func(context.Context) error { db.Close(); return nil }},
	app.Adapter{Name: "events", Run: pub.Run, Close: pub.Close}, // before the servers!
	app.Adapter{Name: "http", Run: func(ctx context.Context) error { return httpapi.Run(ctx, r, cfg.HTTPAddr) }},
)
```

**Registration order matters:** the publisher is registered before the servers, so on shutdown (reverse close order) it drains *after* all in-flight requests have finished publishing. Nothing is lost in a graceful stop.

A feature subscribes its policies and projectors in its composition root:

```go
// features/coupon/feature.go
func New(db *postgres.Client, pub *events.ChannelPublisher) *Feature {
	// ...ports, use-cases...

	pub.Subscribe(events.Handler{
		Name:   "coupon-stats-projector",
		Events: []string{"CouponUsedEvent"},
		Handle: func(ctx context.Context, e ddd.DomainEvent) error {
			return statsProjector.Handle(ctx, e.(domain.CouponUsedEvent))
		},
	})
	// ...
}
```

The handler adapter type-switches/asserts to the concrete event type — the Go analog of narrowing a union.

## Semantics, stated plainly

- **At-most-once, in-memory.** Events die with the process; there is no retry queue. Correct for same-service reactions (projections can be rebuilt, policies re-triggered); anything that must survive a crash belongs to the outbox.
- **Handler errors are logged, not retried.** A handler that needs retries owns them.
- **A panicking or failing handler never affects other handlers** or the publisher itself.
- **Full buffer → inline dispatch** (never blocking the publisher): under extreme backlog, delivery degrades to synchronous rather than deadlocking shutdown.

## Anti-patterns

| Anti-pattern | Why it is bad | The right way |
|-------------|-------------|---------------|
| Dispatching events inside the transaction | Handlers read uncommitted state; ghost events on rollback | Commit-gating via `ddd.AfterCommit` (the publisher does this) |
| Business-critical, must-not-be-lost reactions on the channel publisher | At-most-once, dies with the process | Transactional outbox |
| Publisher registered after the servers in `app.Run` | Shutdown drains before requests stop publishing — events lost | Register `events` before the servers |
| Handler doing long, retryable work inline | Blocks the dispatch loop | Keep handlers fast; enqueue heavy work |
